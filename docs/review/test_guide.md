# What the tests show

Generated by `python scripts/make_test_guide.py` from the test files. Each *Shows* line is a sentence to say in the review: what the test proves and why that matters.

**444 tests in total** (parametrised tests count once per function here; pytest runs each parameter set separately).

## Unit tests — 239 tests in 13 files

One function or class at a time. Everything outside it is replaced by a small fake.

### `tests/unit/test_attachment_processor.py` — 31 tests
Unit tests for enp/attachment_processor.py: reading real (tiny) files of every supported type.

- `test_pdf_by_extension_when_gmail_says_octet_stream` — Shows: Gmail often labels files application/octet-stream, so the extension decides.
- `test_unsupported_types_return_none` — Shows (decision A22): legacy .doc, RTF and zip files are not read.
- `test_same_named_attachments_are_told_apart_by_size` — Shows (A22.3): two files called report.pdf are separated by their byte size.

### `tests/unit/test_chrome_rules.py` — 9 tests
Unit tests for the Chrome intent gate, the privacy filters and the YouTube Shorts classifier.

- `test_phase1_needs_five_seconds` — Shows: a page seen for under 5 seconds is thrown away.
- `test_evaluate_requires_one_intent_signal` — Shows: exposure is not enough; one of the four intent signals must also be present.
- `test_is_application_page` — Shows: Slack/Notion/Jira pages are private (title only), their public sections are ordinary pages.
- `test_canonicalize_url_removes_tracking_parameters_and_fragment` — Shows: the same article from a newsletter or an ad becomes one row (dedup).
- `test_strip_secret_query_params_keeps_the_rest` — Shows: tokens never end up in a stored URL.
- `test_sensitive_pages_are_never_captured` — Shows: login, payment and account pages are recognised from host, path or query keys.
- `test_ordinary_pages_are_not_sensitive` — Shows: the filter does not swallow normal pages.
- `test_skipped_pages_and_domain_extraction` — Shows: GitHub issue pages are skipped, domains are lower-cased host names.
- `test_classify_video_type` — Shows: Shorts are detected from the URL path first, then from a duration under 60 s.

### `tests/unit/test_retrieval_logic.py` — 31 tests
Unit tests for the deterministic retrieval steps: RRF fusion, quality check, widening, routing, effort score.

- `test_rrf_score_adds_one_over_k_plus_rank_per_branch` — Shows: an item in both branches outranks an item in only one, with the exact formula from the design.
- `test_rrf_never_boosts_recent_items` — Shows (CLAUDE.md §2.3): recency is a prohibited feature; a newer date never changes the order.
- `test_rrf_ties_are_broken_by_id_not_by_date` — Shows: equal scores give a stable, deterministic order.
- `test_rrf_empty_branches_and_pool_cap` — Shows: nothing in, nothing out; the pool never grows past RRF_POOL_SIZE.
- `test_rrf_drops_semantic_hits_that_break_the_source_filter` — Shows: a FAISS-only hit from the wrong source is held to the same rules as the keyword branch.
- `test_rrf_drops_semantic_hits_before_the_anchor_or_time_filter` — Shows: time_relation 'after' and the time filter are applied to hydrated semantic hits.
- `test_time_helpers_ignore_bad_input` — Shows: an unparseable timestamp or time_filter is ignored instead of crashing the search.
- `test_route_after_evaluate_quality` — Shows: weak results are widened at most 3 times, then the closest matches are still shown.
- `test_effort_score_ignores_how_recent_the_item_is` — Shows (CLAUDE.md §2.3): created_at never enters the score.

## System tests — 10 tests in 2 files

One whole user journey through the app, for example a page visit that ends as a cited answer.

### `tests/system/test_capture_to_answer.py` — 7 tests
System tests: one whole user journey through the running app, from the browser extension to a cited answer.

- `test_a_page_is_captured_enriched_found_and_cited` — Shows: the whole product works end to end. A visited page becomes a cited answer to a natural question.
- `test_what_the_llm_is_allowed_to_see` — Shows (CLAUDE.md §2.6): the model gets the question and bounded text, never database rows or the whole store.
- `test_private_pages_never_enter_the_memory` — Shows (CLAUDE.md §2.6): login pages, mail and GitHub issues are discarded at the door, so they can never be found.
- `test_a_deleted_item_disappears_from_answers` — Shows: 'delete' really removes a memory from retrieval (soft-deleted rows are never searched).
- `test_a_follow_up_question_uses_the_chat_history` — Shows: multi-turn chat. The second question carries the first one's history and may skip the search.
- `test_the_agent_can_never_exceed_six_llm_calls_through_the_api` — Shows (CLAUDE.md §2.5): even a model that searches forever is stopped after 6 calls, over HTTP.
- `test_settings_stop_capture_immediately` — Shows: the user's capture switch works for the very next page, and pausing never touches stored memories.
